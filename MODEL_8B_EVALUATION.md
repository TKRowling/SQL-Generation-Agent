# AskMe 8B Model Evaluation

This evaluation supports the model choice documented in [ARCHITECTURE.md](ARCHITECTURE.md). Model quality is measured inside AskMe's deterministic checker, bounded recovery, and read-only execution boundaries.

## Decision summary

The Cloudflare 8B model is viable for an AskMe pilot.

**Tested model**

```text
@cf/meta/llama-3.1-8b-instruct-fast
```

It completed all five live tests through AskMe's complete guarded pipeline:

```text
Progressive schema discovery
→ SQL generation
→ deterministic query checking
→ PostgreSQL execution
→ result summarization
```

The production `.env` was not changed during testing.

## SQL examples generated by 8B

### Count

```sql
SELECT
    COUNT(*) AS transaction_count
FROM bank_transactions;
```

### Branch ranking with join

```sql
SELECT
    b.record_name AS branch_name,
    SUM(bt.amount) AS total_transaction_amount
FROM branches b
JOIN bank_transactions bt
  ON b.branch_id = bt.branch_id
GROUP BY b.record_name
ORDER BY total_transaction_amount DESC
LIMIT 5;
```

### Monthly analysis

```sql
SELECT
    date_trunc('month', t.transaction_ts) AS month,
    COUNT(*) AS transaction_count,
    SUM(t.amount) AS total_transaction_amount
FROM bank_transactions t
WHERE t.transaction_ts >= CURRENT_DATE - INTERVAL '6 months'
GROUP BY date_trunc('month', t.transaction_ts)
ORDER BY month DESC;
```

The monthly query executes successfully, but the desired six-calendar-month expression should be:

```sql
WHERE transaction_ts >= date_trunc('month', CURRENT_DATE) - INTERVAL '5 months'
  AND transaction_ts < date_trunc('month', CURRENT_DATE) + INTERVAL '1 month'
```

This weakness occurred with both 8B and 70B, so it should be addressed through the runtime skill, golden tests, and date-semantics validation rather than by retaining 70B alone.

## Strengths observed with 8B

- Generated valid PostgreSQL.
- Passed AskMe's deterministic query checker.
- Used approved tables and columns.
- Generated a correct foreign-key join.
- Produced correct aggregation and ordering.
- Executed successfully against the live database.
- Produced readable summaries.
- Worked with progressive schema context instead of the full schema.
- Did not require weakening any security control.

## Weaknesses observed

- Ambiguous questions may return IDs instead of friendly names.
- Date-window semantics need stronger deterministic or prompt-level rules.
- This five-question test is not large enough to prove production accuracy.
- Complex business definitions are still absent from the metadata catalog.

## Recommendation

Use the 8B Fast model for the next controlled pilot and evaluation phase:

```env
CF_AI_MODEL=@cf/meta/llama-3.1-8b-instruct-fast
```

Do not make the final production decision from five questions. Before full replacement:

1. Build a golden set of at least 50–100 approved banking questions.
2. Compare 8B and 70B using result equivalence, not SQL text alone.
3. Measure first-attempt correctness, recovery rate, latency, tokens, and cost.
4. Include joins, date logic, ambiguity, follow-ups, empty results, and security cases.
5. Require 100% blocking for destructive and restricted-data requests.

## Suggested deployment policy

For the pilot:

```text
Default model: 8B Fast
All SQL: deterministic checker
All execution: read-only PostgreSQL role
Maximum SQL attempts: 3
Complex/failed questions: log for evaluation
70B: optional controlled fallback, not automatic until policy is approved
```

This approach reduces cost while preserving AskMe's application-level safeguards.
